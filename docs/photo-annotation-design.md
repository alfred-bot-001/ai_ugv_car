# 人物照片标注

2026-10-04，用户授权在主控台浏览采样照片、查看识别关键信息与原片，修正人物和分类，独立保存人工标注用于后续调优和训练。

## 数据与职责

模块运行在老大 Mini 的 `robot-console`，复用 admin 登录。老三继续采集和推理，电视继续展示。标注不会调用硬件控制，也不会自动训练或替换在线模型。

- 采样目录维持 `deploy/ai-tv-pet-console/tmp/pose-review`。新增样本同时保留原始 JPEG 字节、绘制骨架和姓名的审核 JPEG、原始推理 JSON；JSON 最后原子提交。旧样本只有审核图，页面明确告知缺少无标注原片，不通过裁剪或修补伪造原片。
- 人工数据单独保存到 `deploy/ai-tv-pet-console/state/photo-labels`。每个确认或排除样本复制来源图、可用原片与推理元数据，保留不可变修订记录和最新人工结果。即使临时采样日后删除，已标注数据仍可查看。
- 模型预测与人工标签分别保存。每个人独立标注身份、姿态和动作，保留模型关键点、跟踪号、人脸框、得分、同帧来源、模型与规则版本及图片校验值。姿态与动作不能合并为一个分类。可补充遗漏人物、移除误检人物或排除整张照片；手工新增人物未人工标定坐标时不伪造关键点。
- 状态为待标注、已确认、已排除。编辑使用 expected_revision 乐观并发控制，避免多页面覆盖；保存历史可追溯。用户点击保存才产生人工结果。
- `dataset.jsonl` 汇总最新确认标签，排除样本不进入训练清单。原片缺失标记清楚，训练前可筛掉；照片不上传第三方，标注本身不改变人脸特征库。
- 目录权限 0700，文件 0600。限定样本文件名，拒绝路径遍历与符号链接，有界读取、分页查询，文件操作在线程完成，避免阻塞设备事件循环。

## 页面与接口

`/photos`：照片卡片列表、计数、审核状态/姓名筛选、分页、识别信息、图像切换和逐人编辑。桌面列表与审核工作区并列，手机使用单列工作区。主控台提供可触达的“照片标注”入口。

| 接口 | 用途 |
| --- | --- |
| GET `/api/v1/photos` | 分页列表、状态和姓名搜索、总计 |
| GET `/api/v1/photos/{id}` | 预测、人工标签和图片可用性 |
| GET `/api/v1/photos/{id}/image?kind=annotated\|original` | 登录后读取图像 |
| POST `/api/v1/photos/{id}/annotation` | 保存修订或排除，校验 CSRF 和来源 |
| GET `/api/v1/photo-labels/export` | 下载最新确认样本的 JSONL 清单 |

全部数据和图片接口要求有效会话，响应不缓存；图片没有静态公开路径。页面编辑冲突提示重新载入，会话失效返回登录。原始人脸相似度与姿态规则得分不显示为准确率。人脸与骨架只能在同帧且唯一关联时合并，不能把一个姓名应用到画面内所有人。

## 批量管理与人物分类（2026-10-04）

- 批量删除默认范围为人工标注：删除当前人工结果与修订文件，机器采样照片、原片和预测保留，照片恢复为待审核。删除文件移动到 Mini 私有回收区，不再出现在训练清单。操作必须由用户勾选并确认；服务器预先校验整批版本和路径，失败回滚，避免部分删除。删除后修订号继续递增，旧页面不能用 revision=0 覆盖。
- 删除对话框另提供“照片、原片和全部标注”：支持待审核与已标注照片，连采样图、原片、推理 JSON 和永久训练样本包一并移入私有回收区。列表和图片接口不再可见，保留删除标记避免旧副本复活；未选照片不受影响。进程启动及每次公开读写之前恢复未完成事务；存储故障持续时拒绝访问，避免新标注覆盖尚未恢复的数据。
- 列表分类采用人工已确认人物（爸爸、妈妈、儿子及自定义名称），每张照片在各人物分类中最多计一次。人物与姿态组合筛选要求同一人物同时匹配，例如“爸爸 + 坐着”不会选中爸爸站着、儿子坐着的照片。默认列表仍可查看待审核机器识别，人物分类导出严格只采用人工已确认结果。
- 支持选中照片批量导出，及按人物/姿态分类导出。ZIP 包含原片（存在时）、识别标注图、原始预测 JSON、人工标签和训练 JSONL；多人照片保留全部人工人物，另记匹配人物编号，避免把其他人错误当作训练背景。导出不重新绘制旧识别图，也不把无原片审核图称为原片。
- 批量请求最多 200 张、ZIP 展开数据最多 256 MiB；有界流式写入本地临时文件，正常下载、客户端断开、构建请求取消及服务关闭均清理临时文件。用户可分批勾选导出。数据接口要求登录，变更及导出 POST 校验 CSRF 与 Origin，原 JSONL 导出继续保留。
- 页面将姿态判断明确显示为站着、坐着、躺着，以及蹲着、蜷缩、无法判断。识别判断与人工修正分别展示，姿态和挥手等动作独立分类。只有人脸、缺少有效人体关键点时显示无法判断，不凭人脸推测站坐躺。

| 新接口 | 用途 |
| --- | --- |
| GET `/api/v1/photos?identity=&posture=&label_source=` | 人物/姿态组合筛选及人工人物分类计数 |
| POST `/api/v1/photo-labels/export.zip` | 勾选或按人工人物分类导出带图片的 ZIP |
| POST `/api/v1/photo-labels/delete` | 批量删除，scope 为 labels 或 photos，校验每张 expected_revision |

## 验证与交付

验证人工分类不混入模型猜测、同人组合筛选、多人导出全图标签与匹配人物、ZIP 内容/大小/边界/清理、整批删除的预检/回滚/并发冲突/版本单调及重新标注。真实生产标签只读核验，不代替用户执行删除。

验证认证/CSRF、访问边界、多人物、旧原片缺失、新原片字节一致、保存隔离、修订冲突、导出排除、源样本丢失后数据保留，以及桌面和手机实际编辑流程。执行 Ruff、Mypy 和完整 pytest/coverage >=80%，打包 wheel 部署到 Mini 持久运行目录，检查真实页面、图片授权、公网健康与设备重连。实机验证不修改真实家庭照片的人工标签。
