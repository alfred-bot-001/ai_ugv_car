# 主控台「地图与导航」页面设计

版本：0.1；日期：2026-10-15；状态：M1 的只读监控部分已于 2026-10-21 实现（页面 `/navigation`，浏览器通道 `/ws/nav`，另加摄像头和导航日志）；2026-10-22 加上控制：开始/保存建图、加载地图、设置位置、「去这里」、取消、内嵌圆盘，命令经主机服务 `ugv-navd` 执行（见部署记录）。摆正、缩略图、地图管理和 M3 尚未实现。依赖 [ROS2 建图与自主导航设计](ros-navigation-design.md) 中已经在车上运行的 ugv-nav 0.3.4（SLAM Toolbox、Nav2、`ugv-navctl`）。

## 1. 目标

在 `car.aimaker.vip` 新增「地图与导航」页面：

1. **实时看建图**：小车建图时，网页上的栅格地图边走边长出来，同时显示小车位置、朝向、走过的轨迹和当前激光点。
2. **边看边开**：同一页内嵌现有的底盘圆盘，用户可以一边看地图一边遥控补全。
3. **管理地图**：保存、命名、删除、设为默认；在已保存的地图上定位。
4. **在地图上指挥**：设置当前位置、点击「去这里」、编辑并运行巡航路线；所有运动都要显式确认，急停始终可见。

## 2. 参考的成熟方案

| 方案 | 借鉴什么 | 不直接采用的原因 |
| --- | --- | --- |
| RViz2 / Foxglove Studio | 图层模型：栅格地图 + 机器人模型 + 激光 + 全局路径 + 目标；2D Pose Estimate 和 2D Goal 的「点下去、拖出朝向」交互；固定坐标系 `map` | 面向开发者，不适合家长使用；Foxglove 需要直连 ROS（foxglove_bridge 或 rosbridge） |
| Vizanti（厂家 ugv_ws 自带） | 手机友好的 2D 正交视图、双指缩放、点选目标和航点、离线可用 | 依赖 rosbridge 端口直连 ROS，绕过登录和 Mini，违反架构约束 3 和 5 |
| 扫地机器人 App（石头、科沃斯等） | 建图时地图「长出来」的实时感；机器人图标和走过的轨迹；地图旋转摆正；多地图管理；「去这里」；禁区 | 闭源，只借鉴交互 |
| Nav2 / SLAM Toolbox 自身 | `/map` 1 Hz 整图、`map_saver`、序列化位姿图、keepout 过滤 | 这些是数据源，页面需要自己组织 |

结论：**交互参考扫地机 App，图层和工具参考 RViz/Vizanti，数据链路沿用我们自己的 Pi → Mini → 浏览器**，不开放 rosbridge 或 foxglove_bridge 端口。

## 3. 数据链路

```text
ugv-nav 容器                          Pi 代理                   Mini 主控台                 浏览器
──────────────                        ─────────                 ──────────                 ──────
/map (1 Hz)      ┐                                              缓存最新地图（新打开的
TF map→base (10Hz)├─ nav_relay 节点 ──UNIX 流套接字──▶ 新 WSS 通道 ──▶ 页面立即拿到整图） ──/ws/map──▶ Canvas 渲染
/scan (降采样 5Hz)│   编码与限流        nav.sock(0600)      /internal/.../nav   鉴权、Origin、CSRF
/plan、目标、状态 ┘
                                      ◀── RPC：nav.* ◀───── HTTP /api/v1/nav/* ◀──────── 按钮与地图点选
```

- **为什么单开一条 WSS 通道**：地图 PNG 每次几 KB 到几十 KB，不能和控制通道的 challenge/租约消息挤在一起，以免拖慢停车链路。做法与现有的 video/audio 通道一致。
- **编码**（容器内 `nav_relay`，属于 `ugv_nav_tools`）：
  - 地图：栅格变化时才发；3 色调色板 PNG（空闲、障碍、未知），附带 `resolution`、`origin`、`width/height`、`seq`、`stamp`。家庭场景约 400×400 格以内，每张 ≤30 KB，1 Hz 足够。地图更大时再加 64×64 分块，只发脏块（与 Foxglove 和 map_server 的增量思路相同）。
  - 位姿：`map → base_footprint`，10 Hz，`{x, y, yaw, stamp}`。
  - 激光：转换到 map 坐标，降采样到 ≤180 点，5 Hz。
  - 路径与状态：Nav2 全局路径（变化时发）、当前目标、模式（mapping/localization/idle）、SLAM/AMCL 是否正常、授权窗口剩余秒数、桥安全门的最近原因（前方障碍、卡住等）。
- **新鲜度**：每类数据都带时间戳。页面超过 3 s 没收到位姿就显示「数据中断」，不能把旧位置当成实时位置（ARCHITECTURE 约束 7）。
- **命令**：浏览器 → Mini `POST /api/v1/nav/{mapping|save|localize|pose|goal|patrol|cancel}` → 控制 WSS 上的 `nav.*` RPC → Pi 代理调用 `ugv_nav_tools.navctl` 的同一套逻辑（写 `arm.json`、切换模式、调用 `ugv-ros-op`）。授权窗口、桥安全门和 Pi 看门狗都不变；浏览器始终碰不到 ROS 和 UART。

## 5. 地图画布

- **渲染**：Canvas 2D。收到新地图 PNG 时用 `createImageBitmap` 解码一次，缓存为位图；每帧用 `requestAnimationFrame` 按当前视图矩阵绘制位图，再画叠加层。位姿在两次更新之间做线性插值，看起来是连续移动。支持高 DPI（`devicePixelRatio`）。
- **图层**（可单独开关，选择存在 `localStorage`）：栅格地图、激光点、轨迹（最近 300 个位姿）、全局路径、目标和航点、车体轮廓（按导航用的 0.17 m 半径画，让用户看到车占多大地方）、网格和比例尺。
- **配色**：空闲为浅色，障碍为深色，未知为浅灰加细斜纹，便于一眼看出「还没探过的地方」。深色模式下有对应配色。
- **视图操作**：滚轮或双指缩放、拖动平移、「跟随小车」开关（建图时默认开启）、「摆正」：用户把墙转成水平或竖直，旋转角按地图保存。SLAM 地图的坐标轴是按小车起点朝向定的，所以墙通常是斜的，扫地机 App 也是这样处理的。
- **坐标**：画布像素 ↔ map 坐标的换算集中在一个纯函数模块里，带单元测试；地图原点、分辨率、y 轴翻转和显示旋转都在这里处理。

## 6. 交互流程

### 6.1 建图（本期重点）

1. 「开始建图」→ 确认框：「将清空当前未保存的地图，进入建图模式。小车不会自行移动。」→ `nav.mapping`。
2. 页面进入建图态：跟随小车，显示已覆盖面积（空闲格 × 0.0025 m²）、用时和 SLAM 状态；用户用内嵌圆盘遥控补全。
3. 可选「原地扫一圈」（4 段原地转向，每段单独授权、需要确认）：扫清起点四周，包括雷达车尾盲区。
4. 「保存地图」→ 输入名称（字母、数字、`_`、`-`，或自动生成 `room-YYYYMMDD`）→ `nav.save` → 地图进入列表，生成缩略图。
5. 后续版本：「自动探索」（`explore_lite`），在授权窗口内按前沿点逐段探索，任何异常立即停止。

### 6.1a 自动探索建图（2026-10-23 实现）

建图时点「自动探索」，老三自己把房间走一遍：

1. `ugv-navd` 的 `explore` 任务每段先在容器里跑 `ugv-ros-op frontier`：读 SLAM 当前地图和位姿，找出「已知空地挨着未知区域」的前沿（`ugv_nav_tools/frontiers.py`，纯函数带测试）。前沿长度不到 0.30 m 的忽略；长前沿按 1 m 见方切段；每段的目标放在附近 1 m 内、离墙至少 0.35 m（安全门在 0.30 m 处停车，仍在 0.10 m 到达范围内）、离未知区至少 0.20 m（车身完全落在已知空地，规划器不允许穿未知区）的已知空地上，并且要能沿离墙至少 0.20 m 的已知空地走到；朝向对着那段边界，让雷达看过去；按路程由近到远排序。拥挤的房间里可能找不到安全目标，此时提示用遥控补窄处。
2. 取第一个目标，按普通「去这里」走一段：每段单独开有限授权窗口（≤120 s），第一段过 10.0 V、之后过 9.5 V 电量门槛，导航桥、安全门、卡住检测、定位健康全部照常。
3. 没到达的目标记下来，以后不再选；连续 3 段没到达、出现安全停车、取消，或满 30 段 / 20 分钟，就停止。没有能安全开到的前沿时提示「探索结束」，由用户点「保存地图」。
4. 页面在任务行显示「第 N 段 · 已探索 X m² · 用时」，地图上用蓝色箭头标出这一段的目标；「取消导航」随时停止。

### 6.2 定位与「去这里」

1. 在地图列表里选择地图 →「在此地图上定位」→ `nav.localize`（AMCL）。
2. 「设置当前位置」：在地图上按下并拖出朝向（与 RViz 的 2D Pose Estimate 相同）→ 激光点与墙重合，说明定位正确。
3. 「去这里」：按下拖出目标朝向 → 确认框显示直线距离、预计时间和「小车将自主移动」→ `nav.goal` → 显示规划路径和授权倒计时；随时可以「取消」或急停。

### 6.3 巡航路线

在地图上依次点选航点（可拖动、可删除、可调整顺序），设置圈数（≤10）→ 保存为这张地图的路线 → 「开始巡航」（确认）→ 显示当前第几圈、第几个点，以及每段的结果。报告来自 `reports/patrol-*.json`。

### 6.4 安全与提示

- 每个会让车动的操作都要二次确认；急停在所有状态下可见。
- 授权窗口剩余秒数实时显示；窗口结束会显示「已自动停车」。
- 桥安全门的停车原因直接显示成中文，例如「前方 0.30 m 内有障碍，已停止前进」「车轮在转但车没动，已停车」（卡住检测，TODO）。
- 页面断线、退出登录或会话被撤销：停止拉取数据；Pi 侧已有的失联停车机制照常生效。

## 7. 接口草案

| 方向 | 接口 | 说明 |
| --- | --- | --- |
| 浏览器 ← Mini | `WS /ws/map`（子协议 `console.map.v1`） | 先发缓存的整图，再推送 `map`（二进制：4 字节长度 + JSON 元数据 + PNG）、`pose`、`scan`、`plan`、`state`（JSON） |
| 浏览器 → Mini | `GET /api/v1/nav/maps` | 地图列表（名称、面积、时间、缩略图 URL） |
| 浏览器 → Mini | `GET /api/v1/nav/maps/{name}/preview.png` | 缩略图，私有接口，不挂静态目录 |
| 浏览器 → Mini | `POST /api/v1/nav/mapping` / `save` / `localize` / `pose` / `goal` / `patrol` / `cancel` | 都需要登录、CSRF、Origin；`goal` 和 `patrol` 写入审计 |
| Mini ← Pi | `WSS /internal/v1/agents/laosan/nav` | 新的设备通道，鉴权方式与 video/audio 相同 |
| Pi ↔ 容器 | `ai-tv-pet-agent/nav/stream.sock`（0600） | 容器写入编码后的数据帧；Pi 代理转发并做限流 |

## 8. 隐私

地图就是家里的平面布局：只存在 Pi 的私有目录和 Mini 的私有缓存里，只能通过登录后的私有接口访问，不进 Git，不上传第三方。删除地图时，Pi 和 Mini 两边一起删。

## 10. 工程约定

- 新代码放在现有包里：`ugv_nav_tools/nav_relay.py`（纯编码函数与 rclpy 节点分开）、`tvpet_pi/nav_stream.py`、`tvpet_console` 的 nav 路由和 `web/map.html`、`map.js`、`map.css`；坐标与编码逻辑写成纯函数并配单元测试；ruff、mypy strict，覆盖率 ≥80%。
- 前端沿用现有页面的风格、图标和 CSP（不引入外部 CDN）；Canvas 以外不依赖第三方库。
